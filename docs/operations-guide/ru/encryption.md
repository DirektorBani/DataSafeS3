# Шифрование объектов

Это шифрование байтов объекта. Это не [field encryption](field-encryption.md) секретов в метаданных и не [инъекция окружения из Vault](secrets-vault.md).

Три состояния:

| Состояние | Заголовок / значение бакета | Ключ |
|-----------|-----------------------------|------|
| Открытый текст | нет | нет. Байты на диске — те, что прислал клиент |
| SSE-S3 | `AES256` | `STORAGE_SSE_MASTER_KEY` на каждом узле. Vault не вызывается |
| SSE-KMS | `aws:kms` и необязательный id ключа | Vault Transit, когда заданы `STORAGE_KMS_PROVIDER=vault-transit` и адрес. До этого тот же ключ сервера оборачивает ключ данных, а провайдер в метаданных остаётся `local` |

Бакет без значения по умолчанию и PUT без заголовка шифрования остаются открытым текстом. SSE-S3 из 1.5.0 классифицируется один раз и дальше читается как открытый текст. См. [upgrade.md](upgrade.md#обновление-до-v160).

Шифрование включается на вкладке **Настройки** бакета или через S3 `PutBucketEncryption`. На Postgres или HA консоль просит подтвердить, что все узлы уже 1.6.0. Живой узел 1.5.0 даёт HTTP 409 `cluster upgrade in progress`. Сначала закончите поочерёдное обновление.

**Настройки → Vault (KMS)** — необязательный клиент Transit: адрес, AppRole или токен, проверка и статус по узлам. Политики, TTL кэша и то, что crypto-shred не стирает, — в [kms-vault.md](kms-vault.md).

**Зашифровать существующие объекты**, **Повернуть ключ** и **Уничтожить ключ** на той же карточке бакета. Уничтожение спрашивает имя бакета. Дальнейшее чтение любого объекта этого бакета, ссылка обмена и presigned GET — HTTP 403 `Ключ шифрования уничтожен, файл недоступен навсегда`.

Ряд Grafana **KMS** (доступность по узлам, латентность, кэш DEK, задачи) описан в [monitoring.md](monitoring.md#kms). Ряды Vault отсутствуют, пока Vault не включён.

## Известный предел: локальный GET не сверяет файл

Если файл объекта уже лежит на диске этого узла, S3 `GET` отдаёт эти байты. С сохранённым ETag и размером они не сравниваются. Повреждённая локальная копия — это HTTP 200. Копия, принятая от другого узла, сверяется с ETag в метаданных до записи. Этот локальный путь чтения — нет. Учтено, в 1.6.0 не исправлено.

## Сравнение с MinIO AIStor Free

MinIO OSS под AGPLv3 заморожен: вендор пишет, что эта кодовая база больше не сопровождается ([pricing](https://www.min.io/pricing)). Текущий продукт — AIStor, ему нужна лицензия ([licenses](https://docs.min.io/aistor/operations/licenses/)).

Список возможностей — страница лицензий, не краткий текст на странице цен. Там AIStor Free — лицензия одного узла, а следующее есть только в Enterprise Lite / Enterprise и на Free отклоняется с `XMinioPaidTierLicenseRequired`:

- распределённое развёртывание (несколько узлов)
- репликация (site, bucket или batch)
- шифрование на диске, включая запись с запросом server-side encryption, `PutBucketEncryption`, создание ключа KMS и пакетную ротацию ключа

Страница цен описывает Free как один узел без оплаты, а Enterprise — как линейку из нескольких узлов. Где та страница говорит «полный набор возможностей», а страница лицензий относит шифрование и репликацию к платному тарифу, отказ назван на странице лицензий.

Open-source KES устарел. Сопровождаемый форк KES и MinIO KMS лицензируются как enterprise ([legacy key management](https://docs.min.io/kms/legacy-key-management/)).

DataSafeS3 1.6.0 — не этот продукт. SSE-S3 и SSE-KMS работают без лицензии AIStor. Vault Transit необязателен. Один узел без Vault и без `STORAGE_KMS_*` не открывает соединение с KMS. HA — существующая аренда лидера в Postgres, не site replication AIStor. Это не заявление о совпадении API с MinIO или AIStor. Путь копирования — [migrate-from-minio.md](migrate-from-minio.md).
