# Описание функциональных характеристик DataSafeS3

**Версия:** 1.7.1  
**Вид:** серверное программное обеспечение, S3-совместимое объектное хранилище с веб-консолью  
**Поставка:** исходный код, образы контейнеров, Helm-чарт, пакеты `.deb` и `.rpm`  
**Интерфейс:** русский и английский

Назначение: хранить объекты на инфраструктуре заказчика, выдавать их по S3 API и управлять доступом, сроками и аудитом из консоли. Продукт не требует публичного облака для администрирования.

Термины: [glossary.md](glossary.md). Матрица вызовов S3: [compatibility.md](compatibility.md).

---

## 1. Состав

| Часть | Функция |
|-------|---------|
| `datasafe-storage-server` | S3 API (порт 9000), Admin API, `/healthz`, `/metrics`, Swagger `/api/v1/docs` |
| Веб-консоль | Вход, бакеты, объекты, ключи, профиль, администрирование |
| Метаданные Bolt | Учёт на одном узле, файл `metadata.db` рядом с объектами. Отдельная СУБД не нужна |
| Метаданные PostgreSQL 16 | Необязательно. Нужны, когда несколько узлов делят учёт |
| `storage-cli` | Перенос с MinIO, служебные команды |
| Мост Kafka | Отдельный процесс, стартует только при непустом `STORAGE_KAFKA_BROKERS` |

Клиенты в каталоге `clients/` (синхронизация рабочего стола, мобильная оболочка) к обязательной установке сервера не относятся.

---

## 2. Режимы работы

### Один узел

Один процесс, свои байты на диске, метаданные Bolt. Так устроены production Compose, пакет и чарт без `cluster.enabled`. Kafka, NATS, Vault и PostgreSQL не запускаются.

### Несколько узлов

Общая база PostgreSQL, у каждого узла свой том объектов. Процесс копирует записанные байты на узлы, которые объявили адрес. `STORAGE_HA_ENABLED` выбирает одного писателя арендой. Чтение S3 с ведомого уходит на лидера. Это не стирающее кодирование между серверами и не автоматическое переключение зоны доступности.

Скрипт повышения реплики PostgreSQL (`scripts/ha/promote.sh`) переводит старую основную базу в режим только чтения и вызывает `pg_promote`. Повторный запуск безопасен. Время, через которое ведомый забирает аренду писателя, близко к длительности аренды (при 30 с — около 26 с).

### Кластер установщика

Интерактивный установщик умеет собрать инвентарь нескольких Linux-ВМ и в режиме DryRun показать планы Patroni, etcd, HAProxy или keepalived. Запись на машины — только с явным применением. Этот контур не заявлен как готовая многозональная эксплуатация.

## 3. S3 API

Поддерживаются path-style URL и подпись SigV4, регион по умолчанию `us-east-1`.

| Операция | Поддержка |
|----------|-----------|
| Список, создание, удаление, Head бакета, регион бакета | да |
| Put, Get, Head, Delete, Copy объекта | да |
| ListObjects и ListObjectsV2, до 1000 ключей и продолжение | да |
| Составная загрузка | да |
| DeleteObjects, до 1000 ключей, Quiet, ошибка по ключу, контрольная сумма | да, с 1.7.0 |
| Версионирование и маркеры удаления | да |
| Метки объекта | да |
| Политика бакета, подмножество операторов, включая Deny и `aws:SourceIp` | да |
| Предподписанный GET | да, ключом пользователя. Корневой ключ установки предподпись не делает |
| Предподписанный PUT | частично: `Content-Type` может быть не подписан. Предподписанный DELETE отклоняется |
| Заголовки шифрования `AES256` и `aws:kms` | да. `aws:kms` зовёт Vault Transit только если провайдер настроен, иначе ключ сервера |
| Object Lock, срок хранения, юридическое удержание | да. Обход GOVERNANCE — заголовком и правом `s3:BypassGovernanceRetention`. COMPLIANCE и удержание не обходятся |
| Истечение жизненного цикла по префиксу | да. Переход класса, истечение нетекущих версий и фильтр по меткам отклоняются |
| Конфигурация уведомлений бакета | сохраняется и уходит в очередь, если приёмник настроен |
| Хвостовые контрольные суммы aws-chunked (CRC32, CRC32C, SHA-1, SHA-256, CRC64NVME) | да |

Не реализованы: ACL объекта и бакета, сайт S3, API CORS, Select, Restore, API конфигурации репликации и инвентаризации Amazon, Accelerate, Requester Pays, Object Lambda, виртуальный хост бакета.

Проверено автоматическим прогоном, когда клиенты есть в `PATH`: aws-cli v2, MinIO Client `mc`, rclone, restic. Удаление префикса у этих клиентов опирается на DeleteObjects.

ETag одиночного PUT для открытого текста — MD5 тела. У шифрования и составной загрузки ETag не равен MD5 открытого текста. Локальное GET не сверяет байты с сохранённым ETag повторно. Копия, принятая от соседа, сверяется.

## 4. Веб-консоль

- Вход по паролю, смена пароля, мастер первого запуска (внешний S3 можно пропустить).
- Обзор, бакеты, браузер объектов, загрузка и скачивание.
- Ключи доступа и квоты использования.
- Профиль, TOTP и WebAuthn.
- Пользователи, группы, роли, арендаторы.
- Журнал действий и выгрузка.
- Шлюз репликации: подключение, правило, расписание, последняя ошибка.
- Страница доставки событий.
- Страница миграции с MinIO: печатает команды, учётные данные источника в браузер не принимает.
- Настройки шифрования бакета и статуса Vault по узлам, когда Vault включён.
- Язык интерфейса: русский и английский.

Снимки экранов: [руководство пользователя](user-guide.md).

## 5. Доступ и идентичность

- Роли консоли: user, operator, administrator.
- Доступ к бакету выдаётся пользователю и группе.
- LDAP: поиск пользователей и групп, фоновая синхронизация, для боя требуется TLS (`STORAGE_LDAP_REQUIRE_TLS`).
- OIDC: вход через внешнего провайдера. Признак MFA в токене (`amr` / `acr`) учитывается политикой. Опасное действие всё равно требует локальный второй фактор.
- MFA администратора: TOTP или ключ безопасности. Политика может запретить работу без фактора.
- Ограничение частоты входа (`STORAGE_RATE_LIMIT_LOGIN`).
- `aws:SourceIp` в политике — это TCP-сосед. Заголовок `X-Forwarded-For` читается только от сетей из `STORAGE_TRUSTED_PROXIES`.

## 6. Защита данных

- SSE-S3 на ключе сервера (`STORAGE_SSE_MASTER_KEY`). Новый объект шифруется, если заголовок или политика бакета этого просят, а не потому что ключ просто задан.
- SSE-KMS через Vault Transit — необязательно. Без адреса клиент не создаётся. Промах кэша при лежащем Vault — HTTP 503, частичный объект не пишется. Кэш расшифровывает, пока не истёк `STORAGE_KMS_DEK_CACHE_TTL` (по умолчанию 5 минут).
- Ротация версии ключа, переупаковка существующего объекта без чтения байтов и уничтожение ключа (чтение после уничтожения — HTTP 403).
- Шифрование отдельных полей метаданных (секреты LDAP, OIDC, внешнего S3) — необязательно, `STORAGE_FIELD_ENCRYPTION_ENABLED`.
- Блокировка объекта и юридическое удержание.
- Секреты в ответах настроек, журнале и `/healthz` не возвращаются.

## 7. События

Очередь исходящих событий хранится в тех же метаданных, что и изменение объекта. Доставка at least once, порядок по объекту внутри одного приёмника, после исчерпания попыток (по умолчанию 20) строка становится «мёртвой».

Приёмники, каждый необязателен:

| Приёмник | Когда работает |
|----------|----------------|
| Вебхук | Есть включённый вебхук |
| Уведомление бакета | У бакета задан URL |
| NATS, в том числе JetStream, если поток покрывает subject | Задан `STORAGE_NATS_URL` |
| Kafka | Задан `STORAGE_KAFKA_BROKERS`. Мост `/usr/lib/datasafe/datasafe-kafka-bridge` стартует только тогда. SASL PLAIN без TLS отвергается |

Пустой список приёмников не открывает брокер. Узлы кластера друг с другом через Kafka не разговаривают.

Метрики доставки и пример оповещений лежат в поставке Prometheus. Страница консоли показывает состояние без запроса к брокеру.

## 8. Наблюдаемость

- `GET /healthz` — состояние и версия.
- `GET /metrics` — Prometheus. Токен `STORAGE_METRICS_TOKEN`, если задан.
- Дашборд Grafana **DataSafeS3 Overview** в профиле мониторинга установщика и в прежнем чарте.
- ServiceMonitor текущего чарта выключен, пока его не включат.
- Журнал процесса: stdout контейнера или `journalctl -u datasafes3` у пакета.
- Внешний приёмник журнала (Elasticsearch, Loki) настраивается в консоли и в простой установке не обязателен.

---

## 9. Перенос и резервная копия

- `mc mirror` и `rclone sync` копируют текущие байты. Версии, блокировку и IAM они не переносят.
- `storage-cli migrate from-minio` копирует версии, маркеры удаления, Object Lock, метки, пользовательские метаданные и те операторы политики, которые сервер умеет проверить. Повтор не пишет ту же версию источника второй раз.
- `storage-cli migrate from-minio iam` заводит пользователей, группы, служебные учётки и политики, которые сервер может применить. Секреты MinIO не копируются. LDAP и OIDC источника не импортируются.
- Резервная копия одного узла — весь каталог данных (база и объекты) с остановкой записи или снимком тома. Копия только базы или только файлов бакет не восстанавливает.

---

## 10. Ограничения, которые входят в характеристику

- Нет полного языка политик IAM Amazon и нет ACL.
- Нет виртуальных хостов бакета.
- Нет автоматического multi-AZ и нет erasure между узлами как режима эксплуатации.
- Локальное чтение не пересчитывает ETag.
- Kafka, NATS и Vault не являются частью минимальной установки.
- Мобильные и настольные клиенты в `clients/` не входят в характеристику сервера v1.7.0 как обязательная функция.

Установка этих режимов: [installation.md](installation.md).
