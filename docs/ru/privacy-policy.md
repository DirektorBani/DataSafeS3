## 1. О чём эта политика

DataSafeS3 — программа, которую организация ставит на свои серверы. Различаются два контура.

1. **Программа у заказчика.** Сервер, консоль и бакеты работают в контуре того, кто программу установил. Поставщик продукта этот контур не видит и к нему не подключается.
2. **Сайт проекта.** Если он опубликован, на нём принимается только заявка на демонстрацию. Других форм, личных кабинетов и рассылок на сайте нет.

Текст ниже описывает оба контура. Он не заменяет политику организации, которая эксплуатирует свой сервер DataSafeS3: для данных в бакетах оператором является эта организация.

---

## 2. Программа не собирает данные пользователей в адрес поставщика

Установленный сервер:

- не отправляет поставщику содержимое бакетов, журналы, учётные записи и ключи доступа;
- не содержит телеметрии и не обращается к лицензионному серверу (лицензия Apache-2.0, отдельного ключа активации нет);
- не требует учётной записи у поставщика, чтобы пуск состоялся.

Куда процесс ходит по сети, решает администратор установки: LDAP и OIDC организации, необязательные вебхуки, NATS, Kafka, Vault, внешнее S3 шлюза репликации, приёмник журналов. Пока эти адреса не заданы, соответствующих соединений нет. В production без `STORAGE_DEV` исходящий HTTP процесса разрешён только на публичный HTTPS.

Персональные данные, которые администратор сам положил в бакет, завёл в пользователя консоли или получил из своего LDAP, обрабатывает **оператор этой установки**, не поставщик продукта.

---

## 3. Какие данные появляются внутри установки

Их создаёт оператор, и они остаются у него.

| Данные | Где лежат | Зачем |
|--------|-----------|--------|
| Логин, хэш пароля, роль, привязка к арендатору | метаданные Bolt или PostgreSQL | вход в консоль |
| Ключ доступа и секрет ключа | метаданные | подпись S3 |
| Объекты и их ключи | каталог данных | то, что загрузил пользователь |
| Журнал действий | метаданные, срок по умолчанию 90 дней | разбор действий |
| Секреты LDAP, OIDC, Vault | метаданные, в закрытом виде, в ответы API не отдаются | вход и шифрование, если их включили |

Оператор сам определяет основание обработки, сроки и состав этих данных. Удаление пакета или контейнера не удаляет каталог данных, пока оператор не сотрёт том.

## 4. Сайт: только заявка на демонстрацию

На сайте проекта, когда он доступен по адресу из шапки, посетителю предлагается оставить заявку на демонстрацию.

Состав заявки ограничивается тем, что человек ввёл в форму (как правило, имя, организация, почта и текст вопроса). Иные персональные данные через сайт не запрашиваются. Учётной записи на сайте нет. Платёжных данных сайт не принимает. Файлы cookie для слежения за посетителем и сторонние счётчики в этот контур не входят: если они появятся на сайте, политика будет обновлена до их включения.

Заявка используется, чтобы ответить на просьбу о демонстрации, и не передаётся для рекламы третьим лицам. Срок хранения заявки: [ЗАПОЛНИТЬ: срок хранения заявки на демонстрацию].

Пока адрес сайта в шапке не заполнен, заявку можно направить на datasafes3@yandex.ru. Это тот же контур: письмо с просьбой о демонстрации, без отдельной базы на стороне программы.
