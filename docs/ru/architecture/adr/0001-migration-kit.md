# ADR 0001: набор переноса MinIO → DataSafeS3

English: [0001-migration-kit.md](../../../architecture/adr/0001-migration-kit.md).

**Статус:** частично заменён [ADR 0007](0007-minio-s3-copier.md)  
**Дата:** 2026-07-10  
**Релиз:** v1.1.1

Чеклист, рецепты rclone и aws-cli и `scripts/migrate/minio-cutover-smoke.ps1` остаются. Копирование объектов — `storage-cli migrate from-minio` (ADR 0007). Импорт IAM — `storage-cli migrate from-minio iam` с v1.6.0: пользователи, группы, служебные учётки и политики, которые этот сервер умеет применить. LDAP и OIDC сообщаются и не импортируются. Секреты MinIO не копируются.

## Контекст

Тем, кто уходит с развёртывания, совместимого с MinIO, нужен описанный переход на DataSafeS3 без заявления о побайтовой совместимости API и без обещания полного импорта IAM.

## Решение

Поставить набор для самостоятельного переноса: руководство эксплуатации (EN/RU), рецепты rclone и aws-cli, чеклист перехода (`internal/migrate`) и `scripts/migrate/minio-cutover-smoke.ps1`. Байты объектов ехали стандартными инструментами синхронизации S3. ADR 0007 добавляет рядом встроенный копир S3.

## Последствия

- Быстрая поставка в Community и небольшая нагрузка на поддержку.
- Политики, которые сервер не умеет проверить, не применяются молча: оператор видит предупреждение.
- Будущие проверки могут переехать из скриптов в `internal/migrate`, не меняя историю для оператора.
