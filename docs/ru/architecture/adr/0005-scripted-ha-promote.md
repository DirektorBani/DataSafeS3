# ADR 0005: скриптовое повышение реплики HA

English: [0005-scripted-ha-promote.md](../../../architecture/adr/0005-scripted-ha-promote.md).

**Статус:** принято  
**Дата:** 2026-07-10  
**Связано:** `scripts/ha/promote.sh`, `scripts/cluster/promote.sh`

## Контекст

v1.1.0 привёз лабораторные схемы HA. Вопрос «что, если основная база умерла» не должен превращаться в заявление уровня Patroni.

## Решение

Предпочесть **скрипты** (`scripts/ha/`, `scripts/cluster/`) с проверкой отставания, ограждением только на чтение и ожиданием здоровья. Пакет `internal/ha/promote` хранит только коды выхода. Контроллера переключения внутри процесса нет. Журнал изменений не должен писать «автоматический multi-AZ».

Старую основную базу ограждают `ALTER SYSTEM SET default_transaction_read_only = on` до `pg_promote`. Этот файл не реплицируется, поэтому повышенная реплика остаётся доступной на запись. Неудачное продление аренды лидера сразу помечает процесс хранилища как не-лидера. Лаборатории Patroni вместо этого понижают старую основную базу (она снова входит в recovery).
