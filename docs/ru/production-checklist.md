# Чеклист перед боевым запуском

English: [production-checklist.md](../production-checklist.md).

Пройдите список до того, как один узел станет основной копией. Форма одного узла: один контейнер, Bolt и том. `STORAGE_DEV` остаётся false. Установка из `.deb` или `.rpm` — тот же узел на Bolt: правьте `/etc/datasafes3/datasafes3.env`, затем `systemctl enable --now datasafes3`. Удаление пакета не стирает `/var/lib/datasafes3`. См. [linux-packages.md](linux-packages.md).

## TLS

- Поставьте Caddy, другой обратный прокси или Ingress чарта перед консолью и S3 API.
- Профиль `tls` production Compose читает `fullchain.pem` и `privkey.pem` из `deploy/compose/production/certs`.
- `values-production.yaml` чарта включает TLS Ingress. Secret сертификата создаёте вы.
- Клиентам S3 нужен сертификат прокси, иначе проверка TLS не пройдёт. Адресация остаётся path-style.

## Учётные данные

- Замените `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, `STORAGE_ADMIN_PASSWORD` и `STORAGE_JWT_SECRET`. Процесс пишет предупреждение, пока стоят исторические значения, а `STORAGE_STRICT_SECRETS=true` отказывается стартовать.
- В Kubernetes используйте `auth.existingSecret`. Чарт эти значения по умолчанию не везёт, и `production: true` без Secret не отрисуется.
- Смените пароль консоли при первом входе и завершите мастер настройки.
- Задайте `STORAGE_METRICS_TOKEN`. Без него `/metrics` на порту API открыт любому, кто до порта дотянулся.

## Что торчит наружу

- Не публикуйте порт 9000 на внешнем интерфейсе, если TLS уже завершает прокси. Production Compose привязывает его к `127.0.0.1`.
- Не отдавайте `/metrics` с публичного прокси. Caddyfile production этого не делает. Снимайте `storage-server:9000/metrics` во внутренней сети с bearer-токеном.
- `STORAGE_DEV=true` — лабораторный переключатель. В production Compose и в чарте он выключен.

## Копии и восстановление

- База Bolt — `metadata.db` внутри `STORAGE_DATA_DIR`, рядом с файлами объектов. Копируйте весь каталог. База без файлов или файлы без базы бакет не восстанавливают.
- Остановите процесс или снимите снимок тома, чтобы база и файлы совпали. Пофайловое копирование живой базы Bolt может порвать страницу.
- При метаданных PostgreSQL снимите дамп базы и снимок тома объектов каждого узла. В одних метаданных байтов нет.
- Пароль администратора, секрет S3, секрет JWT и `STORAGE_SSE_MASTER_KEY` (если задан) храните не на томе данных. Новый процесс с другим ключом SSE не прочитает объекты, запечатанные старым.
- Восстановление: верните каталог и запустите тот же или более новый образ. Прежде чем перепрыгивать версии, прочитайте [руководство по обновлению](../operations-guide/ru/upgrade.md).

## Мониторинг

- `GET /healthz` — проверка процесса. JSON содержит `status` и `version`.
- Снимайте `/metrics` с bearer-токеном. Примеры оповещений: `deploy/docker/prometheus/alerts.yml`.
- Чарт умеет создать ServiceMonitor (`monitoring.serviceMonitor.enabled`). Токен — ключ `metricsToken` Secret `auth`.

## Обновления

- Прочитайте заметки [1.7.1](../../CHANGELOG.md) и руководство по обновлению.
- Снимите копию выше до смены образа.
- Для того, что нужно повторить, тяните тег версии (`v1.7.1`), а не `latest`.
- На нескольких узлах закончите проход, прежде чем включать функцию, которой старый бинарник не понимает. Затвор шифрования 1.6.0 — образец: смешанный кластер отказывает в новой функции, пока каждый узел не станет текущим.

## Один узел остаётся одним узлом

Установка по умолчанию не запускает Postgres, Kafka и NATS. Добавить их позже можно. Kafka и NATS принимают события. Через них pod объекты не делят.
